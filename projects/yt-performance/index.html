Overview

Predicting a video's views in absolute terms mostly measures how big the channel is. This project asks a sharper question: given only the thumbnail and the title, will this upload do better or worse than its own channel's recent average? A deployed service answers it before the video goes public, so creators can compare thumbnail and title options with a ranking signal instead of a hunch.

Leakage guard
0

subscriber features used. The stored count is the channel's current size, not its size at publish time, so the model never sees it.

What it predicts
target = log(1 + views) − log(1 + trailing_avg_views)

trailing_avg_views is the mean views of the channel's 5 most recent prior uploads, so a video never sees itself. A target above zero means the video beat its channel's recent average; predicted views are recovered by inverting the formula.

Architecture

A real service, end to end

Browser → Vercel (Next.js UI, per-IP rate limit) → Caddy (HTTPS, API key, 5 MB cap) → FastAPI running CLIP and the ensemble on an Oracle Cloud Ampere A1 VM, with Airflow handling ingestion, embedding and drift monitoring.

Where things stand
  • Serving: early-fusion ensemble (v2)Token-level RATF, 5 seeds
  • Fallback: late-fusion model (v1)Still loadable by the API; rollback is one path change
  • In validation: automatic retrainingBuilt on the feat/auto-retrain branch; the DAG stays paused until it passes
