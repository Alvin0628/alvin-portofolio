Technical

How a thumbnail and a title become a score.

Frozen CLIP tokens go in, cross-attention mixes three streams, a small Transformer reads them jointly, and five seeds vote.

Ingest

YouTube Data API into Postgres (pgvector); thumbnails stored in MinIO.

Embed

Frozen CLIP ViT-B/32 tokens: image 50 × 768, title 32 × 512.

Fuse

RATF: two cross-attention rounds, then a joint Transformer.

Serve

FastAPI behind Caddy, with a Next.js UI on Vercel.

Chronological split

Train on the past, test on the future

The test set is strictly later than training. The tabular scaler and the genre vocabulary are fit on training rows only, so validation and test never leak into preprocessing.

Subscriber count is dropped from the inputs entirely: the stored value is the channel's current count, not its count at publish time.

Token-level early fusion

Instead of one vector per modality, the model keeps every token and lets the streams attend to each other.

Stream 1
Image
CLIP ViT-B/32 · frozen

The CLS token plus 49 patch tokens, 768 dimensions each.

50 tokens

Stream 2
Title
CLIP text tower · frozen

32 token states of 512 dimensions plus a padding mask. L = 32 truncates only 0.59% of titles.

32 tokens

Stream 3
Tabular
Feature tokenizer

23 continuous features, one token each, plus a genre token. Trailing average views, duration and title statistics.

24 tokens

The RATF mechanism

Two rounds of cross-attention, then one joint read

Six parallel cross-attention blocks let each stream query the other two (title from image, title from tabular, image from title, and so on). The updated tokens join a CLS token to form 107 tokens, which a 3-layer Transformer (d = 192) reads together before a small MLP head outputs the score. About 3.0M parameters per member.

Tried and dropped

A learned reliability gate

The gate was meant to weight each modality per sample. It saturated at its upper bound (about 2.0 for image and tabular in 5 of 5 seeds), so it behaved as a global ×2 scale. Freezing it at identity scored higher on test in 4 of 5 seeds, and that is what ships.

What stabilised training

Modality dropout

Randomly hiding the title or image during training. Without it, one of three seeds collapsed to 0.237 validation Spearman and stopped at epoch 3; with it, every seed landed between 0.311 and 0.324.

Choosing the configuration

Three Optuna stages on validation only. The test set was never opened during tuning.

Search

Risk-adjusted TPE

Each trial is scored as mean validation Spearman over two seeds minus 0.5 × std, so a configuration that collapses on one seed is penalised. Trial 0 of every stage re-runs the previous winner, which keeps the reported gains honest. Stage A ran 40 trials, B and C 24 each.

Confirmation

Six candidates, three fresh seeds

The selection rule was fixed in advance: adopt a candidate only if it beats the default by at least 0.005. The winner, c24, scored a risk of 0.379 against 0.265 for the default and was the most stable across seeds.

Serving and MLOps

Inference service

FastAPI on an Oracle Cloud ARM VM

Browser → Vercel (Next.js, per-IP rate limit, adds the API key) → Caddy (HTTPS, key check, 5 MB body cap) → FastAPI running the CLIP token extractor and the 5-member ensemble in Docker Compose on arm64.

The response carries the score, expected views with a typical-error band (plus or minus one test MAE in log space, not a confidence interval), and the spread across ensemble members.

Safe rollouts

Bundles, not code

The model ships as a single bundle of about 58 MB (config, scaler, genre vocabulary, five state dicts). It stays out of git, and its SHA-256 is pinned in a sidecar JSON. Rolling back means pointing MODEL_BUNDLE_PATH at the previous bundle.

Orchestration

Apache Airflow

ingest_new runs monthly and chains into embed_new and train_model, with monitor_drift alongside. Every task runs in a worker container against Postgres and MinIO. Drift checks (KS tests plus channel-mix shift) are informational and never block anything.

Defense in depth

Four layers

A Vercel per-IP rate limit, then an API key checked at Caddy, then a 5 MB body cap, with Postgres, MinIO and Airflow bound to 127.0.0.1.

Automatic retraining

In validation on the feat/auto-retrain branch. The pipeline is built; its DAG stays paused until it passes.

python -m early_fusion.retrain all
export→tokens→split→train→package→verify→gate

Only new videos are embedded (an incremental token store). Five seeds are refit on train+val with the production recipe, packaged into one bundle that records its train_end and snapshot hashes, verified, and only then judged.

01

Hard gate

The candidate must beat a linear trailing-average baseline. This catches broken runs.

02

Soft gate

A paired bootstrap on the same test rows (2,000 resamples). Rejected only if the interval's upper bound is below −0.01, so ties go to the newer model.

03

Anchor gate

The candidate is also compared with a fixed v1 reference that is never overwritten, so small regressions cannot accumulate unnoticed.

Atomic swap

A crash never half-promotes

A promotion copies the live bundle to prev, then replaces latest atomically per file; if the process dies in between, latest stays the old, intact bundle. The API restarts only when a swap was actually applied, and retraining is skipped when fewer than 100 new videos have arrived.
