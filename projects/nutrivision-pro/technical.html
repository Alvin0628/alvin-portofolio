Refine

Resolve

Log

System architecture

Frontend

Next.js

/diary 16-nutrient progress vs. target, date history.
/profile user data → daily target.

Firebase-based auth with client-side route protection via AuthProvider / ProtectedRoute.

Backend

FastAPI

Modules for inference, nutrition, diary, users, feedback, and vision refinement, with Redis-backed caching.

Tokens are verified independently on every endpoint — the client-side route guard is a UX layer, not the security boundary.

Deployment & CI

The Dockerized API runs on AWS EC2 and pulls the model artifact from S3 at container startup instead of baking it into the image. The web app is on Vercel, with separate GitHub Actions workflows for API and web.

Why these classes

Built for a real plate, not a benchmark

Most public food-recognition datasets skew Western. Tofu, tempeh, sambal and squid are everyday staples here that generic models miss entirely — the class list was chosen to actually work on the food people around here eat.

Coming Soon — Continuous Training

The next phase will introduce a continuous training pipeline that allows the model to improve from real user feedback over time.

Feedback loop

User Feedback as Training Data

User-uploaded images become additional training data through two feedback scenarios.

Scenario 1

False negatives

Users identify food that was missed by the model, with SAM2-assisted auto-segmentation helping generate accurate segmentation labels.

Scenario 2

False positives

Users can remove incorrect detections, providing feedback that can be converted into valid training labels.

Data

Dataset Expansion

Newly validated labels from user feedback will be combined with the existing base dataset stored in S3 to create an updated training dataset.

Trigger

Continuous Training

When enough new feedback has accumulated and the configured threshold is reached, GitHub Actions will trigger a dedicated training container.

Infrastructure

Isolated Training Infrastructure

Training will run in a separate, on-demand container, independent from the production container currently serving the API and Redis, so model training does not interfere with inference services.

Release

Automated Model Improvement

The newly trained model will go through the continuous training workflow before being introduced back into the production inference system.

Goal

Build a self-improving ML system where every user upload can feed back into the model, so the food segmentation model continuously improves.

User upload→Feedback→SAM2-assisted labeling→Dataset expansion→Threshold-based retraining→Updated model
